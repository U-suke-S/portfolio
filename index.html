GitHub Pagesで作る
画像入りポートフォリオ

アカウント登録から、応募先に渡せる公開URLの取得まで。パソコンのブラウザだけで進められます。

1. 無料アカウントを作る

  1. GitHubの登録画面を開きます。
  2. 画面に沿ってメールアドレス、パスワード、ユーザー名などを入力します。ユーザー名は公開URLの一部になります。
  3. 本人確認を求められたら画面の指示に従い、GitHubから届くメールでメールアドレスを確認します。
  4. 登録後、サインイン画面からログインします。

認証メールが見つからなければ、迷惑メールフォルダを確認します。ログインできる場合は、プロフィールアイコン → Settings → Emails から認証メールを再送できます。

GitHub公式の登録手順

2. サイトの置き場所を作る

  1. 右上の ＋ → New repository をクリックします。新規作成画面を直接開くこともできます。
項目設定
Owner自分のアカウント
Repository nameportfolio
VisibilityPublic
Add READMEオン

Create repository を押します。main に README.md が表示されれば準備完了です。

この手順の公開URLは https://ユーザー名.github.io/portfolio/ です。Publicを選ぶと、公開ページとリポジトリ内のファイルを第三者が閲覧できます。

3. 画像をアップロードする

  1. パソコンで画像の名前を profile.jpg など、半角英数字の分かりやすい名前にします。PNGなら拡張子は .png のままにします。
  2. Code → Add file → Upload files を開き、画像をドラッグ＆ドロップします。
  3. Commit changes を押し、README.md と同じ階層に画像が並んでいることを確認します。

ブラウザからのアップロードは1ファイル25 MiB、1回100ファイルまで。公開サイト全体は最大1 GBです。GitHub Pagesの上限

4. 画像入りのポートフォリオを作る

① NotebookLMで掲載原稿を用意する

別途NotebookLMで作成したポートフォリオ用の原稿を用意します。自己紹介、経歴、対応できる業務、実績、稼働時間などから、公開したい内容を確認してコピーします。

② ChatGPTまたはClaudeでHTMLを作る

下のプロンプトをコピーして、ChatGPT または Claude に貼り付けます。送信前に「掲載原稿」をNotebookLMの原稿に、「画像の場所と用途」をステップ3でアップロードした実際のファイル名と用途に差し替えます。

画像を README.md と同じ階層にアップロードした場合は ./profile.jpg のように書けます。images フォルダに入れた場合は ./images/profile.jpg です。画像を再添付する必要はありません。どの実績の画像か分かるように、用途も添えてください。

あなたはWebデザイナーです。以下のNotebookLM原稿と、GitHubにアップロード済みの画像を使い、応募先に共有できる日本語のポートフォリオを作成してください。

【掲載原稿】
（ここにNotebookLMで作成した原稿を貼る）

【画像の場所と用途】
（下の例を実際のファイル名と用途に置き換える。使わない行は削除する）
./profile.jpg｜プロフィール写真｜冒頭に配置
./work-01.png｜制作実績の画像｜該当する実績の近くに配置

【希望するデザイン】
（例：白背景、青をアクセントにした、親しみやすいデザイン）

【作成条件】
- GitHub Pagesで公開できる完全な index.html を1ファイルで作る。CSSと必要なJavaScriptはHTML内にまとめ、外部ライブラリやビルドを必要としない構成にする。
- スマホとPCの幅に対応する。冒頭で「どんな人か」「何を任せられるか」が伝わるようにし、原稿にある経歴・実績・稼働条件などを見つけやすく整理する。
- 原稿にない経歴、数値、実績、連絡先、画像を作らない。公開用に渡した情報だけを使う。
- 画像は指定したパスをそのまま使い、大文字小文字と拡張子を変更しない。リポジトリ内の画像には ./ から始まる相対パスを使う。公開用の完全な画像URLが指定された場合は、そのURLを使う。各画像に用途に合ったaltを付け、スマホ画面の幅からはみ出さないようにする。
- 出力は <!doctype html> から </html> までのHTMLコードのみ。説明やMarkdownのコードフェンスは付けない。

③ 生成したHTMLをGitHubに保存する

  1. Code → Add file → Create new file を押します。
  2. Name your file… に index.html と入力します。
  3. AIが出した <!doctype html> から </html> までを編集欄に貼り付けます。
  4. Commit changes… を押し、確認画面で main に直接保存します。

すでに index.html がある場合は、ファイルを開いて鉛筆アイコンから編集します。AIが作ったHTMLをファイルとして持っている場合は Add file → Upload files からも追加できます。

5. GitHub Pagesで公開する

  1. リポジトリ上部の Settings を開き、左メニューの Pages を選びます。
  1. Build and deployment の Source を Deploy from a branch にします。
  2. Branch を main、その右のフォルダを /(root) にして、Save を押します。

公開処理が終わると Settings → Pages に Visit site が表示されます。そこから公開ページを開きます。

PublicリポジトリのGitHub Pagesは無料で使えます。画面下部の「30日間無料」はGitHub Enterpriseの体験版の案内です。

6. 表示の確認とトラブル対処

困ったとき確認する場所
Commit changes が押せないファイル名に index.html が入っているか、編集欄に内容があるか確認。
公開ページが404になる公開URLに /portfolio/ が入っているか、Pagesの設定が main と /(root) か確認。設定直後は数分待ち、反映しないときは Actions で公開処理の状況を見る。
画像だけ表示されないsrc のフォルダ名、ファイル名、大文字・小文字、拡張子をGitHubのファイル一覧と照合する。
文章や画像を更新したいindex.html を編集して main に保存。同じ公開URLで反映を確認する。

共有前にシークレットウィンドウとスマホで公開URLを開き、文章と画像が表示されるか確認します。応募先に共有するのは Visit site で開いたURLです。
